Changelog:
-----
* 2026-11 (2.8.2): CI only, no library change. All workflows moved to the current action majors (checkout, setup-node and codecov v7; github-tag-action v7; create-pull-request v8.1.3), which also puts them on node24 and removes the Node 20 deprecation warning, and the Docker-based `npm-get-version-action` is replaced by two lines of `node -p`. The release version check now diffs `package.json` against the previous commit instead of reading a push payload, so a release can be retried with `workflow_dispatch` (manual dispatch previously failed in the check job). `release-smoke.yml` exercises the release-only steps - npm pack, tag computation, archive - without publishing.
* 2026-11 (2.8.1): No behaviour change. Dead code removed - a write-only field, three unused declarations and two helpers left over from the pre-rewrite XML parser - along with six exports that only their own module used; every bundle is 121-129 bytes smaller. `tsconfig.json` now rejects unused locals and parameters, so the next dead declaration fails CI. The README documents the app bundle footprint against `osmtogeojson` (0 runtime dependencies against 9, and 8.4 KiB gzipped for JSON against 11.6 KiB), reproducible with `npm run footprint`.
* 2026-11 (2.8.0): Tree-shaking: `osm2geojson-lite/xml`, `/json` and `/pbf` each read one format, expose the same API as the default entry and reject the others with an error naming the entry that does read them, so a bundle can leave the unused parsers out (PBF 39.7 KiB, XML 36.0 KiB, JSON 27.7 KiB minified). The default entry still detects all three for mixed inputs such as an XML osmChange applied to a PBF base. Published bundles are now minified (default entry 48.2 KiB / 14.8 KiB gzip, 55% smaller than 2.7.11), and `sideEffects: false` plus the `module`, `unpkg` and `jsdelivr` fields point bundlers and CDNs at the ESM build.
* 2026-11 (2.7.11): Element registration no longer hashes a `type/id` string per element: `RefElements` keeps registration order in an array plus typed indexes, and reference resolution takes the index directly instead of a closure per way. Converting the same 48,472 elements is now 7% faster than osmtogeojson (was 1.3x slower at 2.7.6); element-dense JSON -16%, PBF -11%, dense XML -4% against 2.7.8.
* 2026-11 (2.7.8): Relation members resolve in bulk like way references, relation flattening deduplicates by (way, role) instead of a concatenated key, tags are copied into props once at parse time instead of merged per output feature, and the now-unused deferred-binder machinery is removed. Converting the same 48k-element extract against osmtogeojson: 2.3x slower at 2.7.6, 1.10x now; full paths improve a further 1-9%.
* 2026-11 (2.7.7): Performance: props are built once instead of copied-and-deleted then merged (the delete put the object in dictionary mode), composite ids are computed once per element, way node references resolve in bulk against a typed node index instead of one binder object and closure per reference, and history resolution takes a fast path when ids are already unique. Measured against 2.7.6: PBF -36%, usa.osm -13%, hebei.json -14%, no regression on any fixture.
* 2026-11 (2.7.6): The CommonJS entry is callable again: from 2.7.0 the named exports made `require('osm2geojson-lite')` return `{ default, ... }`, so calling it directly threw. The CJS build now attaches the named exports to the converter function and keeps `default` pointing at it.
* 2026-11 (2.7.4): Test depth: seeded mutation fuzzing over the fixtures, a differential harness against `osmtogeojson` (feature selection on every fixture, exact shape comparison on twenty) and a capped decompression pre-allocation so a corrupt `raw_size` cannot reserve gigabytes.
* 2026-11 (2.7.3): Applying a diff deleted nothing: an osmChange delete names the version being deleted, so a base at that exact version now deletes (equality was treated as a conflict). Real matched base/diff pair from OSM attic data added to the suite.
* 2026-11 (2.7.2): Correctness fixes found by a real-data test corpus: a relation no longer emits the same member node twice (duplicate feature ids), junk `null` entries in `elements` are skipped instead of throwing, an unversioned deletion no longer removes a newer version (XML and JSON now agree), and PBF `int64` fields (`way.id`, `relation.id`, `lat_offset`, `lon_offset`) are decoded exactly instead of being misread as unsigned; malformed length-delimited fields report their wire type; the CLI reads stdin and writes stdout through the process streams instead of `/dev/stdin`/`/dev/stdout`, which fail on Linux when they are pipes. Tests: real PBF/diff/history fixtures, a corpus-wide invariant sweep, corner cases per feature and enforced coverage thresholds.
* 2026-11 (2.7.0): Element-level composition: `toElements()` normalises XML/PBF/JSON into element objects; `mergeOsmChange()` applies an osmChange to a base by version, appending creates and keeping stale entries out while reporting them as conflicts; `applyOsmChange()` returns `{ geojson, conflicts }` and honours `strict`. The XML scanner gained an element-emitting mode that shares the tokenizer with the direct conversion path.
* 2026-11 (2.6.0): The CLI decompresses gzip (`.gz`) and zstd (`.zst`) input, including compressed PBF, and reports bzip2/xz with an actionable hint; the library names the compression container instead of failing with a PBF parse error.
* 2026-11 (2.5.0): Input and history coverage: osmChange (`.osc`) `create`/`modify`/`delete` sections and `action="delete"`; OSM PBF input in the library and the CLI, with a bundled synchronous zlib/DEFLATE decoder that keeps runtime dependencies at zero; full history resolution (newest version wins, deletions become tombstones, references to deleted elements stay unresolved) across XML, JSON and PBF.
* 2026-11 (2.4.0): Role-aware relation member handling: polygon subarea/other roles and node members (stops, admin centres, labels) are emitted independently; route platform members are excluded from relation geometry; member roles stay aligned through late binding.
* 2026-11 (2.3.0): Align relation semantics with OSM: type-based geometry dispatch, empty role treated as outer, old-style multipolygon attribution to the tagged outer way, non-geometry relations no longer synthesized, `visible=false` skipped and derived polygon rings closed.
* 2026-11 (2.2.1): Merge duplicate Overpass/OSM elements (JSON and XML) by version and completeness, filling missing tags/geometry and removing orphaned reference binders.
* 2026-11 (2.2.0): Iterative relation flattening, lazy endpoint-bucket stitching, grid-based inner-ring assignment, consistent finite coordinate/bounds validation, documented missing-coordinate gap semantics, hermetic snapshot tests, CDATA handling, exported `IOptions` and removal of the unused generic `XmlParser`. Added corner-case coverage across the XML scanner, relation flattening, multipolygons and validation.
* 2026-11 (2.1.1): Support arbitrary Overpass custom XML element types (#34) and make circular relation traversal cycle-safe, giving closed cycles a root feature instead of an empty result or stack overflow (#36).
* 2026-11: Feature parity with `osm2geojson-ultra` (Overpass derived geometries, `out center`, `out bb`, `elementId`, `tainted`, custom `polygonTags`, canonical polygon rules) plus duplicate-way de-duplication (issue #48), XML entity decoding and a purpose-built OSM XML scanner. Internal rewrites remove the O(n²) binding/merging paths, cache way endpoint keys, share ring scans and keep coordinates numeric, making the converter roughly 2.5–4.2x faster than ultra on the XML reference datasets and 4.4–20x faster on the JSON ones.
* 2025-08: Give more weight to the order of segments when convering a relation to a line, suppot super relations with more than 1 level.
* 2025-05: Support way order in relataion, improve typescript typeings, added CI for vitest tests.
* 2025-03-03: fixed a few bugs around non-*Polygon features processing and convert it to a pure TypeScript project (codes published to [NPM](https://npmjs.org/) have become TSC compiled from now on).
* 2019-2025: quite a few contributors had fixed quite a few bugs and also contributed some good ideas - thanks for their efforts!
* Late 2018: this repository was created and the initial version was pushed to github - almost around specific usages for myself.
